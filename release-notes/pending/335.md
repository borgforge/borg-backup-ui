- Browse & Restore now respects repository resource locks: browse, download checks, and prechecks report a busy repository clearly, while restore extraction and direct downloads hold the repository lock so matching backup jobs do not start concurrently.
- Restore-held repository locks no longer make the related backup job appear as if a backup run itself was active on the Jobs page.
- Backup starts that are skipped because a restore holds the repository lock are shown as skipped in the live log instead of as failed jobs.
