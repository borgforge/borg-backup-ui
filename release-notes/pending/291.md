Issue #291: Reliable backup.conf rollback timestamps

- Config backup history now shows the snapshot creation time instead of the copied source file modification time.
- Existing backup.conf rollback snapshots without readable metadata fall back to the timestamp embedded in the backup filename.
- The rollback table labels the timestamp column as Created and clarifies the German reason column as the snapshot trigger instead of the currently displayed diff reason.
- Canonical backup.conf migrations now also create a visible Config Backups & Rollback entry with the `canonical_backup_conf_v1 applied` trigger.
