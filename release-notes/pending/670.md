### Improvements

- **Docker start and stop order per job:** Drag containers or use the arrows in the Order list of the job wizard's Docker step. After the backup they start from top to bottom, and before the backup they stop one by one in reverse order, so a database at the top stops last and starts first. A custom order replaces the backup.start.priority groups and their pauses for the listed containers, and no mode waits for application readiness. Without changes, jobs keep the previous behavior with the labels. (#670)
