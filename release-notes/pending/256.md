- Added a dedicated Notifications settings area with Apprise profile management, compact saved-profile summaries, searchable provider selection, dynamic provider URL templates from Apprise metadata, URL validation and test delivery.
- Apprise profile editing now generates provider-specific URL fields from the selected URL format, saves non-secret fields for later edits and keeps password/token values write-only so they can be replaced without being rendered back into the browser.
- Provider URL format selection now exposes all Apprise templates so later ntfy formats with password or token fields can be selected during profile creation.
- Saved Apprise profiles now use a quieter compact summary and avoid duplicate provider labels such as `ntfy (ntfy)`.
- Apprise profiles now receive their selected backup, restore-test and overdue reminder events, using the profile display name as the notification title prefix.
- Existing native ntfy settings are migrated into an Apprise profile during startup, and the separate native ntfy settings UI has been removed.
- Migrated Apprise ntfy profiles now reopen the matching URL-format editor correctly, including token-based templates.
- The Notifications settings area no longer shows the one-time ntfy migration note after the cutover.
- Backup and reminder logs now report delivered Apprise profile names instead of showing the inactive native ntfy channel in the standard event summary.
- The canonical `backup.conf` migration now rechecks completed installations after schema updates, so obsolete native ntfy keys and new Apprise keys are cleaned up automatically on startup.
- Validating an existing Apprise profile now uses the stored write-only URL when no replacement URL was entered, matching the test-notification behavior.
